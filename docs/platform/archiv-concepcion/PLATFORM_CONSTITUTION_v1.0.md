# Purpose

This document defines the constitutional principles of the Embed Engine
platform.

It is the highest architectural authority.

All platform components, architectures and implementations must conform
to this document.

------------------------------------------------------------------------

# Vision

Embed Engine is a Decision Platform.

It does not build pages.

It creates decision experiences.

------------------------------------------------------------------------

# What Embed Engine IS

-   A layered decision platform
-   A Runtime-centered architecture
-   A semantic decision engine
-   A platform for personalized decision experiences
-   A system of Runtime projections for different perspectives

------------------------------------------------------------------------

# What Embed Engine is NOT

-   Not a CMS
-   Not a CRM
-   Not a BI platform
-   Not a workflow engine
-   Not a page builder
-   Not a collection of independent applications

------------------------------------------------------------------------

# Constitutional Principles

## Principle 1

Knowledge precedes Runtime.

## Principle 2

Builder authors knowledge.

## Principle 3

Runtime is the only author of semantic meaning.

## Principle 4

Every application is a Runtime projection.

## Principle 5

Terminals author nothing.

They only project Runtime.

## Principle 6

Perspectives ask different questions.

Runtime answers them all.

## Principle 7

Decision Sessions are transient.

Decision Journey is persistent.

## Principle 8

Identity preserves continuity.

Identity never creates meaning.

## Principle 9

Meaning flows in one direction only.

Knowledge ↓ Runtime ↓ Terminal ↓ Experience

## Principle 10

Every Runtime object has exactly one semantic owner.

## Principle 11

No layer may create semantics owned by another layer.

## Principle 12

AI operates inside Runtime semantics.

It never becomes an independent semantic authority.

------------------------------------------------------------------------

# Platform Layer Model

Authoring Layer ↓ Runtime Layer ↓ Projection Layer ↓ Experience Layer

------------------------------------------------------------------------

# Information Flow

Knowledge ↓ Runtime ↓ Decision Session ↓ Perspective ↓ Terminal ↓
Experience

Interactions may return to Runtime.

Only Runtime may modify semantic state.

------------------------------------------------------------------------

# Design Rules

-   Prefer projections over duplication.
-   Prefer Runtime over local interpretation.
-   Prefer composition over specialization.
-   Separate identity from perspective.
-   Separate permissions from semantics.

------------------------------------------------------------------------

# Evolution Rules

Every future capability must answer:

1.  Which layer owns it?
2.  Who is the semantic owner?
3.  Does it introduce new meaning?
4.  Can Runtime remain the single source of semantic truth?

If these questions cannot be answered consistently, the proposal must be
reconsidered.

------------------------------------------------------------------------

# Constitutional Statement

Runtime creates meaning.

Builder prepares meaning.

Terminals reveal meaning.

Identity preserves continuity.

The platform grows by adding new projections---not by creating new
semantic systems.
